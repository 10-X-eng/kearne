# TECH-010 — Codex App-Server Integration

- **Status:** In progress
- **Decision:** [ADR-0008](../../PLAN/adr/0008-codex-app-server-compatibility.md)
- **Plan:** [Codex app-server harness](../../PLAN/capabilities/17-codex-app-server-harness.md)
- **Official protocol:** [Codex App Server](https://learn.chatgpt.com/docs/app-server)

## Proven in this probe

`probe.py` uses only the Python standard library and starts no model turn. It:

- requires an optional exact Codex version before launch;
- generates stable and experimental JSON Schema bundles from that binary;
- repeats the stable generation and requires semantic equality after JSON canonicalization;
- verifies initialize, thread, turn, stable MCP-status, and local-image contracts;
- proves dynamic tools are absent from the stable thread schema and present only with `--experimental`;
- verifies pre-initialize and repeated-initialize rejection;
- disables ambient MCP servers, creates an ephemeral read-only thread, discovers the local bridge, and calls its typed read tool;
- rejects non-JSON stdout, unexpected stderr, timeouts, and non-zero/forced shutdown.

Run:

```bash
python3 prototype/010-codex-app-server/probe.py --expected-version 0.146.1
```

The JSON result contains source state, binary/schema digests, timings, platform, and protocol outcomes. Generated schema bundles remain temporary because they are derived from the pinned executable.

Codex 0.146.1 emits the aggregate schema definitions in nondeterministic key order. Raw bundle digests can differ while canonical JSON digests match. Drift gates must compare canonical JSON or per-schema semantics, not generated byte order.

The bridge implements the [MCP lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) and [tool contract](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) needed by this probe. It accepts only the named compatible protocol versions, advertises one read-only tool, and contains no Kearne domain implementation.

## Current evidence

[Linux x86-64, Codex 0.146.1](evidence/linux-x86_64-codex-0.146.1.json) passed from clean revision `b5b9603`. App-server negotiated MCP `2025-06-18`, discovered and called the isolated bridge, and shut down on input EOF. Stable generation produced 275 files/2,860,975 bytes; experimental generation produced 349 files/3,344,172 bytes. Initialization completed in 285.464 ms. Timings are one sample, not a performance conclusion.

This proves the scoped Linux handshake, schema, and MCP bridge path. It does not close TECH-010.

## Not yet proven

- authenticated thread and turn lifecycle;
- actual local-image ingestion;
- approval, interruption, stale-call, and crash/restart behavior;
- transcript/credential retention policy;
- packaging and update behavior;
- Windows parity.

These remain TECH-010 exit criteria. This probe cannot justify production support.
